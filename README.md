# Eco Sudar (Bio Energy LLP) - System Documentation

This repository houses the complete ecosystem for **Eco Sudar**, encompassing dual environments: a robust PHP core backend API (`/api`), and a highly reactive React-based Administration Control Panel (`/eco-sudar-control`).

This document serves as the master architectural map designed to onboard new developers and provide exact instructions for deploying the ecosystem into production servers.

---

## 🏗️ 1. Backend Architecture (`/api`)

The Eco Sudar backend is completely custom-built on strict PHP 8. It actively avoids bloated frameworks (like Laravel or Symfony) to guarantee absolutely minimal latency, extreme efficiency, and native compatibility with standard shared hosting environments (such as Hostinger).

### 🛠️ Core Technologies
*   **Engine**: PHP 8.1+ (Strict Typings Enabled globally via `declare(strict_types=1);`)
*   **Database Engine**: MySQL 8.0+ connected securely via standard PDO.
*   **Security Standard**: Stateless JSON Web Tokens (JWT) algorithm `HS256`.
*   **Response Standard**: Unified JSON formatting handled by `Response.php`.

### 📂 Directory & Execution Flow
Every request is funneled through `api/index.php` (via `.htaccess`) which creates an instance of our `Router`.

1. **`api/core/` (The Engine Room)**
   *   **`Router.php`**: An advanced custom router that supports RESTful methodology (`GET`, `POST`, `PUT`, `DELETE`), dynamic URL parameters (e.g., `/users/{id}`), and sequential middleware execution arrays.
   *   **`Request.php`**: Securely intercepts all HTTP requests. It parses JSON payloads, guards against payloads exceeding 8MB, normalizes headers, and exposes a strict library for fetching fields (e.g., `$request->input()`) and enforcing `htmlspecialchars()` sanitizations.
   *   **`Response.php`**: Guarantees output is standardized into fixed arrays (`{"success": bool, "message": string, "data": []}`). It handles HTTP status codes properly (201 Created, 404 Not Found, 422 Validation Failed).
   *   **`Database.php`**: A master singleton PDO wrapper. Includes explicit methodology for complex SQL interactions like `beginTransaction()`, `commit()`, and array-bound `insert()` or `fetchAll()`.

2. **`api/middleware/` (The Gatekeepers)**
   *   **`AuthMiddleware.php`**: The primary gate. It intercepts the HTTP `Authorization: Bearer <token>` header, statically decodes the JWT using our `JWT.php` helper, validates Token Expiration bounds, checks the active database `revoked_tokens` table for forced logouts, and natively injects the decoded `$user` object into the `$request` context recursively.
   *   **`AdminMiddleware.php`**: Sits directly behind AuthMiddleware. Parses the injected `$user` variable and ensures `"user_type" === "admin"`. Emits an immediate HTTP 403 Forbidden on failure.
   *   **`RateLimitMiddleware.php`**: Algorithmic traffic limiter preventing DDoS. Executes lightweight probabilistic database cleanups on the `rate_limits` table and logs client IPs. Hardcoded limits reside in `api/config/app.php`.

3. **`api/controllers/` (The Command Bridges)**
   *   Functions are strictly divided. End-user interactions reside heavily at the root level (`QueryController`, `QuoteController`, `UserController`).
   *   Dashboard operations are completely segregated into the `api/controllers/admin/` folder to prevent any bleed of elevated privileges into public classes. 

### 🔐 Authentication Flow & JWT
Authentication is natively managed by `AuthController.php`. 
*   **Segregated Tokens**: Standard Logins emit *both* an `access` token (valid for 30 days) and a `refresh` token (valid for 180 days).
*   **Silent Renewal**: A client can silently POST their active `refresh` token to `/auth/refresh` to transparently receive a brand new access chain without the end-user needing to re-input passwords.

*   🔗 **[Admin Control Panel API Endpoints Catalog](./admin_api_endpoints.md)**

## 🎨 2. Frontend Architecture (`/eco-sudar-control`)

The Administrative Dashboard orchestrates the vast amounts of telemetry generated by the Eco Sudar platform. Built on Vite, updating the UI takes milliseconds, while Vite natively bundles everything highly optimized for raw static servers.

### 🛠️ Core Technologies
*   **Build Environment**: React 18 powered natively by Vite.
*   **Programming Language**: TypeScript (Interfaces enforce strict shapes on mapped API data).
*   **Styling Architecture**: Tailwind CSS. Complex theme variations are mapped using standardized CSS variables inside `src/index.css`.
*   **Component Architecture**: Composed using the `shadcn/ui` framework tightly binding Radix Primitives with customized Tailwind layouts.

### 🗺️ Data Architecture & Contexts
*   **`src/contexts/AuthContext.tsx`**: Creates a global contextual safety layer hugging the React application. Unauthenticated users are force-routed securely to `/login`. Upon authentication, it writes the login payload directly into standard `localStorage` strings.
*   **`src/lib/api/client.ts`** *(The Backend Bridge)*: This exposes the core `apiFetch()` command. It automatically interrogates `getAuthToken()`, maps standard Request Init formats, natively builds generic TypeScript return shapes, and centralizes error tracking cleanly. **Toggle `MOCK_MODE` to false to enforce live SQL connections!**

### 🧩 Core Modular Map
1. **Operations Matrix**: 
   *    `Products.tsx`, `Orders.tsx`, `Customers.tsx`, `Dealers.tsx`: Maps arrays to rich shadcn `<Table>` variants allowing advanced fuzzy search mechanisms, status tracking, and inline action editing.
2. **Finance Engine**: 
   *    `Invoices.tsx` & `GstInvoicing.tsx`: Generates real-time financial arrays mapping B2B inputs natively. 
3. **Public API Interceptors**:
   *   `Queries.tsx` & `QuoteRequests.tsx`: Specifically designed to read the Minimal Schema implementations. Expects highly optimized data formats connecting your public landing website contact modules and Savings Calculator algorithms into a native, centralized command space.

## 🚀 3. Deployment Pipeline & Setup Checklists

### 💻 3.1 Local Frontend Development
1. Start within the dedicated workspace: `cd eco-sudar-control`.
2. Ensure you have Node.js 18+ or Bun installed.
3. Install package ecosystem: `npm install`
4. Launch the local Vite development instance: `npm run dev`
   * By default, preview dynamically at `http://localhost:8080`.

### 📦 3.2 Compiling the Frontend for Production
1. From `/eco-sudar-control`, run: `npm run build`
2. Vite generates a heavily-optimized, statically mapped folder named `/dist`.
3. Upload the entirety of the contents inside `/dist` to your primary public webspace (e.g. `public_html`).

### ⚙️ 3.3 Deploying the PHP API Ecosystem 
1. The backend expects a unified entrypoint. Upload the entire `/api` folder structure to `public_html/api`.
2. **Crucial Configuration File**: Locate `api/config/database.php`. Overwrite the static credentials to match the MySQL database generated inside your Hostinger dashboard.
3. Establish your routing guardrails. Ensure an `.htaccess` file resides centrally pointing everything blindly to `index.php`:
    ```apache
    <IfModule mod_rewrite.c>
        RewriteEngine On
        # Route logic unconditionally toward index.php
        RewriteCond %{REQUEST_FILENAME} !-f
        RewriteCond %{REQUEST_FILENAME} !-d
        RewriteRule ^(.*)$ index.php [QSA,L]
    </IfModule>
    ```

### 🔗 3.4 Wire Verification Check
To permanently complete the connection linking your deployed API backend with your live Frontend React interface:
1. Open `eco-sudar-control/src/lib/api/client.ts`.
2. Configure `export const MOCK_MODE = false;`.
3. Ensure `export const BASE_URL = "https://api.ecosudar.com/api";` points authentically.
4. Execute your `npm run build` command and deploy the updated static package.
